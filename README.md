# Design Patterns

State Tree pattern: for the ai usage
Event Que and threading: for the audio so that it doesnt block my whole game
Pimpl: for easier compile time for the audio and input
Command Pattern: for the controller input to have an easy way of switching input
Observer Pattern: to communicate between the gameobjects
Service locator: easier switching between audio types and easier to call the audio
